## Overview

The AI-Based Smart Infrastructure Monitoring System is a web application designed to support infrastructure inspection management and AI-based crack image analysis.

The application integrates a Flask backend, SQLite database, and a trained Ultralytics YOLO model. Users can manage infrastructure records and inspections, upload images for crack analysis, view annotated prediction results, and review previously stored AI analysis records.

The project demonstrates the integration of web development, database management, image processing, and computer vision in an infrastructure monitoring workflow.

## How It Works

The application follows a workflow that combines image validation, model inference, result generation, and database storage.

```text
       Image Upload
            |
            v
    Input Validation
            |
            v
      YOLO Inference
            |
            v
   Annotated Result Image
            |
            v
     SQLite History
            |
            v
         Dashboard
```

### Workflow Explanation

1. **Image Upload:** The user uploads an image through the web interface.
2. **Input Validation:** The application validates the uploaded image before processing.
3. **YOLO Inference:** The trained model analyzes the image and predicts potential cracks.
4. **Result Generation:** The application generates an annotated image containing model predictions.
5. **Database Storage:** Analysis information, confidence scores, and image paths are stored in SQLite.
6. **History Review:** Previously recorded analysis information can be accessed through the application.

## Getting Started

### Prerequisites

Before running the project, ensure that you have:

- Python installed and available from the terminal.
- Git installed.
- A compatible environment for the installed PyTorch, Ultralytics, and OpenCV dependencies.
- Sufficient system memory and storage to load and run the trained model.

### 1. Clone the Repository

```bash
git clone https://github.com/Mohd-Shariq-codes/AI-Based-Smart-Infrastructure-Monitoring-System.git
cd AI-Based-Smart-Infrastructure-Monitoring-System
```

### 2. Create a Virtual Environment

#### Windows PowerShell

```powershell
python -m venv ai_venv
.\ai_venv\Scripts\Activate.ps1
```

If PowerShell blocks virtual environment activation because of its execution policy, use an appropriate policy for your environment or activate the environment through another supported method.

#### macOS and Linux

```bash
python3 -m venv ai_venv
source ai_venv/bin/activate
```

### 3. Install Dependencies

Run the following commands after activating the virtual environment.

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

The dependencies include the Flask application packages and the libraries required for image processing and model inference.

> **Environment note:** PyTorch and computer vision packages can have platform-specific requirements. If installation fails, check the official package installation instructions for your operating system and hardware.

### 4. Run the Application

Start the Flask application:

```bash
python app.py
```

When the server starts successfully, open the application in your browser:

**http://127.0.0.1:5000**

Keep the terminal open while using the application. Press `Ctrl+C` in the terminal to stop the development server.

### Important Setup Notes

- The trained model file must exist at the configured path: `runs/segment/ai_models/crack_seg/weights/best.pt`.
- The SQLite database file is excluded from Git. The application is expected to initialize the database when it starts.
- Existing local database records and uploaded inspection images are not included in a fresh clone.
- The screenshots referenced in this README must be added to the repository before they can be displayed on GitHub.

## Database

The application uses SQLite for persistent data storage.

The database supports the following categories of information:

| Data Category | Stored Information |
|---|---|
| Infrastructure | Infrastructure identifiers, names, locations, statuses, conditions, inspection dates, notes, and creation timestamps |
| Inspections | Inspection identifiers, associated buildings, inspection dates, inspector details, statuses, notes, and creation timestamps |
| AI Analysis History | Recorded analysis information, confidence scores, and image paths |

The local database file is named `infrastructure.db` and is excluded from version control to avoid publishing local application records.

Uploaded inspection images and generated AI analysis images are also stored locally. These files are not automatically transferred when another user clones the repository.
